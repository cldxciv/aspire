# Suggested Implementation Plan

## Milestone 0 — Repository and source audit
Deliverable: architecture summary, stack/dependency map, run/build/test commands, asset/content inventory, existing route/API map, risks, and implementation plan. No destructive changes.

## Milestone 1 — Design foundation
Deliverable: responsive site shell, tokens, typography, header/mobile navigation/footer, buttons/forms/cards, image strategy, page metadata baseline.

## Milestone 2 — Public discovery and trust
Deliverable: Home, About, Program directory/detail, Results archive, Centre directory, Resources, Contact. Use verified data; placeholders are visibly development-only.

## Milestone 3 — Admissions conversion
Deliverable: admissions steps, enquiry form with robust validation and server integration, consent/privacy messaging, confirmation/error states, spam protection appropriate to stack.

## Milestone 4 — Portal foundation
Deliverable: student/parent/admin shells and route guards. Connect to an existing approved auth/data system if available. Otherwise leave a clearly labelled preview and document backend requirements; do not simulate security as if it were real.

## Milestone 5 — Quality and launch readiness
Deliverable: responsive, accessibility, security, SEO, performance and cross-browser QA; automated tests where practical; bug fixes; production content checklist; deployment notes.

## Milestone 6 — Owner review and content loading
Deliverable: approval workflow for verified results, programme details, centre data, faculty, testimonials, images, fees, dates, contact information, and legal pages. Publish only approved content.
