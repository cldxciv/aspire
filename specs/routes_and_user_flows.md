# Routes, Navigation & User Flows

Route names are suggested; adapt to the existing application router.

## Public routes
| Route | Purpose | Key content/actions |
|---|---|---|
| `/` | Home | Brand promise, programme discovery, verified outcomes, centre discovery, FAQs, enquiry CTA |
| `/about` | About Aspire | History, teaching approach, values, approved faculty/leadership |
| `/programs` | Programme directory | Cards, filters, programme comparison where appropriate |
| `/programs/:slug` | Programme detail | Audience, curriculum/highlights, schedule/fees only if verified, enquiry CTA |
| `/results` | Results and achievements | Approved results by year/programme; source/context and consent-aware student details |
| `/centres` | Centre finder | Search/filter, verified address, contact and directions |
| `/admissions` | Admissions journey | Steps, enquiry/application form, FAQs, privacy/consent |
| `/resources` | Resources/news index | Searchable articles, exam tips, updates |
| `/resources/:slug` | Article detail | Readable content, related resources, CTA |
| `/contact` | Contact | Verified contact details, enquiry form, directions |
| `/privacy` | Privacy notice | Owner-approved legal text |
| `/terms` | Terms | Owner-approved legal text |

## Portal routes (must be protected when connected to real data)
- `/student` — student dashboard shell.
- `/student/timetable`, `/student/resources`, `/student/progress` — only if the data source and permission model exist.
- `/parent` — parent dashboard shell; only linked/authorized learners.
- `/parent/updates`, `/parent/progress` — only if approved data exists.
- `/admin` — protected admin landing/dashboard.
- `/admin/enquiries`, `/admin/content`, `/admin/centres`, `/admin/results` — protected CRUD screens only after role checks, validation, and audit requirements are implemented.
- `/login`, `/forgot-password` — only if an approved identity/auth system exists; do not build insecure password handling from scratch.

## Key user flows
### Prospective student/parent enquiry
Home or programme page → programme detail (optional) → enquiry form → validation → explicit confirmation with reference if generated by backend → follow-up contact route.

### Find a centre
Home CTA or nav → centre directory → search/filter district → centre detail → call or directions. If location data is incomplete, show “details to be confirmed” only in preview/admin, not as a fabricated public listing.

### Review results
Home results feature → results archive → filter by year/programme → read the context and verified entry. Do not publish placeholder numbers/names.

### Student/parent access
Login through approved identity provider → server validates session and role → route to role-specific dashboard → fetch only authorized records → sign out. Unauthorized requests must be rejected server-side, not merely hidden in the UI.

### Admin enquiry handling
Authorized admin login → enquiry list → filter/status → open enquiry → update status/add note → audit event. Do not expose enquiry records to unauthenticated visitors or students.
