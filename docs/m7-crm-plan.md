# Milestone 7 — Lead generation & admission engine (CRM), Phase 1

Owner request 2026-10-20: "move ahead with the lead generation and admission engine … multi agent to complete this ASAP". Base commit: the home-carousel commit after `a2f3b0b`.

## Decisions (binding)
- **D-037 In-house CRM on the existing stack.** Leads live in the site's SQLite store (`src/lib/db/features/crm.ts`, tables `crm_*`) behind a repository layer (`src/lib/crm/repo/**`) so a later move to Postgres touches only that layer. Single server (as auth). No third-party CRM in Phase 1.
- **D-038 Staff role.** New core role **`staff`** (users table CHECK widened by an append-only core migration that rebuilds `users` safely — foreign keys preserved, verified with `PRAGMA foreign_key_check`). CRM membership lives in `crm_staff` (user id, `crm_role`: `counsellor` | `manager`, optional centre scope). Record-level access, deny by default: counsellor → leads assigned to them; manager → leads of their centre(s) (all if unscoped); admin → everything. Staff never get student/parent portal data beyond what a lead links to.
- **D-039 Leads with consent, honestly.** Every public form submission (hero, admissions, contact) and every tool CTA ("talk to a counsellor" from predictor / mock tests / Ask Aspire / planner) becomes a lead **only with the consent tick already required**; the consent text + version + timestamp is stored with the lead. Forms keep forwarding to the webhook destination if configured; storing in the CRM is the default now (`ENQUIRY_STORE=crm`, can be turned off). Status copy becomes truthful ("received — Aspire will contact you") only when the lead was actually stored. Minors: the form asks for the parent/guardian and the consent line says the submitter is the parent/guardian or has their permission (legal review flagged).
- **D-040 Dedupe, assignment, pipeline.** Phone normalised to E.164 (+91) is the duplicate key → one lead per family, every submission appended as an activity. Auto-assignment: rules by centre and program → round-robin among active counsellors in scope; fallback queue "Unassigned". Stages: `new → contacted → counselling_booked → visited_or_demo → applied → test_taken → offer → enrolled`, or `lost` (reason required). Stage changes, notes, calls, tasks and assignments are activities on a timeline. Follow-up tasks with due dates; "today / overdue" views.
- **D-041 No fake channels (D-033 still applies).** No SMS / WhatsApp / email providers: the UI offers `tel:` and `https://wa.me/` click-to-chat links and records the call/message as an activity — nothing is "sent" by the system.
- **D-042 Privacy & retention.** Lead data is personal data of minors' families: staff-only, audited (who viewed/exported/changed), CSV export admin/manager only and audited, per-lead erase (admin) that deletes personal fields and keeps an anonymised stub for funnel counts, retention period TBC by Aspire (default proposal: delete unconverted leads after 18 months). Privacy notice gets a "Enquiries and admissions" section (lead owns `legal.ts`).

## Implementation notes (2026-10-20)
- **D-039 contract change (CRM-CAPTURE):** every enquiry now requires `consentVersion` (`CONSENT_VERSION = "2026-10-20.v2"`; server picks the consent text from its own registry by version + language) and accepts an optional attribution `context` (page, locale, utm_source/medium/campaign/term/content, tool, predictor toolExam + toolBand, referrer host) — invalid context values are dropped, never a 422. A page loaded before the deploy gets a 422 and the form says "refresh and try again". Webhook payload gains top-level `consentVersion` + `context`; the `enquiry` object keeps its shape.
- **Storage:** `ENQUIRY_STORE` (default `crm`; `off`/`none` = previous behaviour). Responses: `201 received` when stored or forwarded, `500` when neither, `200 not_configured` only with store off and no webhook, `429` for the IP limit or the per-phone cap (5 captures / 24 h, hashed E.164 key).
- **Attribution:** `<AttributionCapture />` is mounted in the (site) layout (sessionStorage only, no cookies). `/api/health` reports `enquiries: connected` when leads are stored.
- **Needs legal review:** the v2 consent line ("parent or guardian, or have their permission"; phone / WhatsApp / email as contact channels), whether the contact form (adults) uses the same line, and the predictor's exam + score band travelling with an enquiry (disclosed on the predictor page and in the privacy notice).
